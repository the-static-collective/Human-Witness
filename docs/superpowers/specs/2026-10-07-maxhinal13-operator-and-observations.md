# MAXHINAL-13 issue #4: bounded extension decisions

This implementation follows the approved 2026-10-06 constellation design and issue #4's explicit bootstrap, transport, SINEW and PNEUMA brief. The supplied archive is the actual source, reconciled atop `e7ce025`; protected design/plan documents were not replaced by archive placeholders. Human Witness's core encounter evidence, actor declarations and legal validity remain separate from this experimental adapter's destination-local consequences.

## Authentication and cryptography

Keep the pinned reLATTE v0 canonicalization, identity domains, P-256 algorithm and signed SB-001 fixture compatibility. Exporting the existing canonicalizer for a typed relation digest does not change canonical bytes or the standard. All live private keys are generated by genesis within their assigned existing Supabase host. No management connector generates or reads them. Source and destination public keys/fingerprints are checked independently; rotation remains an explicit future ceremony.

The requested host-private 256-bit operator capability uses SHA-256 in its private table. Add an expiry timestamp; each scoped CLI ceremony creates temporary tokens with a 30-minute lifetime, protected outside the checkout, and revokes in `finally`. No new authentication primitive is introduced. Host gateway JWT verification is disabled only for these custom-auth protocol functions; operator actions and cryptographic ingress remain checked. Status retains platform JWT verification and the scoped operator optionally supplies a valid JWT only to that same host; no operator capability creation occurs in status mode. An actor string in an edge receipt is a declaration, not identity authentication.

## Durable transport and observations

Use existing private Postgres receipt, event and ancestry tables; persist verified transport HOLD/disposition bodies in the source's own custody before completing its outbox. HOLD-only acknowledgements are durable, while transport remains pending. Terminal destination disposition is immutable. Attempts remain visible after a later successful retry. Add only MAXHINAL payload/backlog indexes and the capability expiry column; no preexisting application tables, schemas or grants are modified.

All node-local SQL paths check the assigned host and logical node before selecting a schema or key. Source-owned receipts cannot mutate a sibling's world. Hosted Postgres uses pinned Postgres.js with `prepare:false` for transaction pooler compatibility.

A protected read-only trace exports public signed bodies and safe attempt codes. Fresh-process replay verifies signatures, exact address binding, destination custody, mandatory HOLD, disposition order, parent scope and parent observation. It does not contact hosts, need pulses, claim original-byte rehash, or infer LIVE transport. Every duplicate is verified, even when it repeats an already counted receipt ID. Each live operator hop also requires separate host-local source and destination trace fetches bound to its expected crossing ID, worlds and particular before onward dispatch. Transport acknowledgement custody cannot substitute for independently fetched destination history. Trace relation observations contain only intermediate HOLD decisions; terminal ACCEPT/REFUSE is exported separately as the signed disposition. Contradictory current snapshots are refused rather than silently merged.

## SINEW

`maxhinal13.proposed-edge/v0` is a closed bounded relation object containing source/destination, reason, fixed evidence scope/payload kind, local parent reference, source proposer declaration and time. Its own canonical hash is an edge ID; the UTF-8 JSON is a new SHA-256-addressed particular. It does not preserve the image's byte identity and cannot overwrite it.

Dispatch signs an existing reLATTE crossing with `SINEW_PROPOSED_EDGE`, and writes only a pending outbox. Destination verifies the typed carrier and signed source-local terminal parent proof before committing HOLD. It leaves the relation held until an authenticated destination operator explicitly chooses ACCEPT, REFUSE or HOLD. ACCEPT is constrained by the destination's native constitution: a Gate ancestry refusal cannot be overridden; Witness ACCEPT yields FORWARD, never ADMIT. A prior REFUSE is terminal; acceptance requires a separate new proposal. A recorded HOLD observation is durable but not a terminal resolution. Relation ancestry may reference a different parent particular precisely because this is a new relation, not byte-identical onward image transport.

Backpressure reports held/pending counts, oldest pending age and a suggested safe action. It has no authority, automatic retry/admission, global scheduler or graph merge. The operator's live SINEW command depends on verified two-host parent evidence; the executable founding witness is explicitly simulation-only.

## PNEUMA

Reuse the existing signed reLATTE receipt carrier with `kind=PNEUMA_PULSE`, `contract_ref=PNEUMA-001`, `semantic_effect=none`, no pre/post/descendant/residual state, and a closed pulse extension. The `pulse:<boot>:<epoch>:<node>` correlation string denotes an ephemeral observation, **not** an actual crossing ID or event inserted into durable history. This choice avoids a second signature standard. Pulse parentage cannot be used to satisfy SINEW's terminal local receipt requirement.

The host emits only node/boot/time/epoch, held/pending counts, last receipt ID and bounded activity. Cache per warm isolate is 60 seconds; absence and stale replay yield observer-local UNKNOWN, reconnection/reboot yields RECOVERING, then bounded QUIET/PULSING estimates. No irreversible world-state is written. The independent cold replay ignores pulses and works with Realtime absent. Optional signed pulses require live host identities, so hosted pulse observation is unearned at the auth boundary.

## Proof order and remaining gate

Integration, deterministic simulation, Deno checks, dry-run/operator runbook, actual denied genesis probes, schema privilege reads and scoped additive hardening are earned independently. Host keys/peers/capabilities remain zero. Reviewed functions are deployed via the existing scoped management connection (genesis v3; ingress/worker/status v1, status with JWT gateway). Authenticated bootstrap, exact-image HTTPS loopback/two-host/13-node route, authenticated live hostile cases, live SINEW, live PNEUMA and physical outage are unearned. The original INVITATION bytes and protected operator configuration are required to continue. The Constellation Rack UI begins **after** the secure two-host crossing, as required by issue #4; no new UI framework is selected before that gate.
